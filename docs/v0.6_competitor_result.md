Run: GitHub Actions, "ProofScope Competitor Comparison", 2026-11-09 UTC. SemantEq v1.4.0 at `f927670`
(its default 20 s per pair). Same 208 pairs: `heldout_oracle` (175, oracle-labelled) and `dev` (33).

## How to read it (do not cite the table without this)

* **Neither tool let a bad pair through.** Neither ever called a non-equivalent pair equivalent.
  SemantEq never called a vacuous pair or an applicability gap "equivalent".
* **Coverage.** ProofScope answered 187/208 with Lean-checked certificates. SemantEq answered 87/208 within its
  default time limit on a GitHub runner, and its time limit is configurable.
* **The 18 disagreements are mostly a difference of definition, not SemantEq errors.** The expected labels use
  ProofScope's pointwise semantics. In 16 of the 18, both statements are true theorems and SemantEq reports that
  the Lean *statement* is weaker or stronger in form. Examples:
  - `n ≤ 2^n` vs `n < 2^n`;
  - `C ∨ n = 3` vs `C` with `C` always true;
  - a mislinked pair `n + 0 = n` vs `n * 1 = n`.

  For formalization review, SemantEq's flag on these is arguably the more useful answer. The clearest SemantEq
  mistake is `o087_s_mod_lt` (a duplicated hypothesis `0 < m ∧ 0 < m` reported as "too strong").
* **What this shows about ProofScope.** It confirms the practical cost of the observability theorem: when both
  statements are true, ProofScope's EQUIVALENT means "same on the domain". It cannot see that a Lean theorem
  states a weaker *true* bound than the reference. The tools are complementary:
  - ProofScope certifies hypothesis-side defects (applicability gaps, vacuity, Lean stronger) and abstains rarely;
  - SemantEq flags weaker-in-form conclusions that ProofScope labels EQUIVALENT.
* **Benchmark caveat.** The cases are ProofScope's own, arithmetic only, so this is not SemantEq's home ground.

**Claim allowed:** "On 208 matched pairs, neither tool made a false equivalence call. ProofScope gave a certified
answer on 187 and SemantEq on 87. Where they disagreed, the difference was almost always a stricter notion of
statement strength in SemantEq, which exposes a blind spot in ProofScope."

**Not allowed:** "ProofScope beats SemantEq" or "state of the art". State-of-the-art superiority has not been
established.
