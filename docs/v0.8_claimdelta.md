# ProofScope v0.8: ClaimDelta, certified statement strength beyond logical equivalence

Base: `entropysherlock/ProofScope` @ `6e32d46cb83e31893e421fba08d94e978dbcdf6b`. Lean 4.34.1, core only.
Numbers marked **LOCAL** come from the author's sandbox. Numbers marked **PENDING** need a GitHub run.

## 1. The problem

Two true theorems are logically equivalent, because each side can be proved separately. Logical
equivalence therefore cannot distinguish a faithful formalization from one that proves a **weaker true**
claim. For example, the reference `∀ n, n < 2^n` and the Lean statement `∀ n, n ≤ 2^n` are equivalent.

v0.6 proved the same limit for ProofScope's pointwise engine (the *observability theorem*). The v0.6
SemantEq comparison showed it in practice: SemantEq flagged such pairs as "LikelyTooWeak", while
ProofScope said EQUIVALENT.

## 2. The idea: compare the claims about the shared symbols, and certify the difference with a countermodel

The method has three steps.

1. **Abstract the shared operators.** `lean/ProofScope/Abstract.lean` elaborates both statements and
   finds the operators they *share* that lie outside the interpreted theory. Under policy
   `LINEAR_CORE_SHARED`, logic and linear arithmetic are interpreted. Everything else both sides use is
   abstracted: `^`, `*` between variables, `%` or `/` by a variable, `Nat.gcd`, `∣` by a variable, and
   so on. Each such operator is replaced by a variable `x`.
2. **Bind to the originals.** The abstracted statements are tied to the elaborated ones by `Iff.rfl`
   certificates (`link_*` obligations).
3. **Certify the relation.** ProofScope then certifies, with the existing gate (tactic → clean
   recompile → standard axioms → kernel replay), one of the following:
   * **uniform entailment** `∀ x, REF x → LEAN x`, which uses nothing particular about the operators;
   * a **countermodel** `∃ x, LEAN x ∧ ¬ REF x`: an interpretation of the operators where the Lean claim
     holds and the reference fails.

For the example above, the countermodel interprets `^` as `fun _ b => b`. Then `n ≤ n` holds for all
`n`, but `n < n` fails at `n = 0`. Verdict: **CLAIM_LEAN_WEAKER**, with the certified countermodel as
the explanation. Recovering the reference from the Lean statement needs a specific fact about
exponentiation (`n < 2^n` itself).

**Separate proofs cannot fake equivalence.** A uniform-entailment certificate must hold for *every*
interpretation of the abstracted operators, so proving `P` and `Q` independently gives nothing.

**Law check (harmless rewriting).** When a separation is found, ProofScope tries to prove the missing
concrete direction using only *equational laws* of the operators plus linear arithmetic. The laws are
commutativity, `pow_two`, `pow_succ`, `gcd_comm`, and similar (SemantEq's notion of allowed library
rewriting). If that succeeds, the verdict is `EQUIVALENT_BY_LAWS`, with the laws listed. Example:
`gcd a b ∣ b` against `gcd b a ∣ b`.

## 3. Soundness (Lean, `lean/ProofScope/ClaimDelta.lean`)

All 15 theorems print "does not depend on any axioms", and `leanchecker --fresh` exits 0 (**LOCAL**;
CI step added).

| Theorem | What it establishes |
|---|---|
| `separation_refutes_entailment` | A countermodel rules out any uniform derivation of the reference from the Lean claim. |
| `entails_specializes` | A uniform entailment is a proof about the actual statements. |
| `strictlyWeaker_not_equiv`, `strictlyWeaker_asymm` | The labels cannot contradict each other. |
| `entails_refl`, `entails_trans`, `strictlyWeaker_trans` | Strength is a **preorder** (partial order on equivalence classes). |
| `incomparable_example` | It is not total: incomparable claims exist. |
| `entails_restrict`, `separation_lifts` | Refinement. Entailment proved with more abstraction survives with less; a countermodel found with less abstraction survives with more. So the separating symbol sets are upward-closed, and **minimal separating sets** are well defined. They are the reported explanation. |
| `no_concrete_separation` | At the actual operators, true statements are never separated (link to the v0.6 observability theorem). |
| `two_pow_strictly_weaker`, `two_pow_concretely_equivalent` | **Counterexample to a stronger reading.** The same pair is strictly weaker as a claim *and* concretely equivalent, so a ClaimDelta separation is not a concrete difference. |
| `add_zero_policy_artifact`, `add_zero_with_law` | **The verdict depends on the policy.** Abstracting `+` with no laws separates `n + 0 = n` from `n = n`; keeping the law removes the separation. This is why `+` is interpreted and why the law check exists. |

## 4. Evidence

### 4a. Development suite `claimdelta_v08` (25 cases, synthetic, written and hashed before the first freeze)

| Run | Exact | Wrong verdicts | Inconclusive |
|---|---|---|---|
| First run, frozen engine (hashes in `CLAIMDELTA_FREEZE.txt`, block 1) — **LOCAL** | 21/25 | **0** | 4 |
| After fixes (suite now development data) — **LOCAL** | 25/25 | 0 | 0 |

**Diagnosis of the 4 first-run misses.**
- Engine bug: typeclass instances (`instHAdd`, `instHSub`) were collected as "symbols". Fixed by recursing
  only into explicit arguments. This affected 2 cases.
- Witness pool lacked patches on the second argument. Fixed by adding second-argument patches. This
  affected 2 cases.
- None of the misses was a wrong verdict.

**Harmless rewrites.** All 12 (commuted products, `gcd` symmetry, `n < 2^n` vs `n + 1 ≤ 2^n`, negation,
swapped conjuncts, equation symmetry, hypothesis rephrasing) produced **no** claim-change verdict in
either run.

Full tables: `docs/v0.8_claimdelta_results.md`; per-case data: `docs/v0.8_claimdelta_results.json`.

| Verdict | Cases |
|---|---|

| CLAIM_LEAN_WEAKER | 36 |
| INCONCLUSIVE | 28 |
| SCHEMA_EQUIVALENT | 14 |

- **New capability.** In 8 cases, v0.6 certified EQUIVALENT (both statements true) and ClaimDelta certifies
  a countermodel showing a weaker Lean claim. ClaimDelta also certified a strength relation in 13 of the 21
  cases v0.6 left INCONCLUSIVE; among them is `n ≤ 2^n` against `n < 2^n`.
- **Agreement with SemantEq.** Where both tools gave a direction (16 cases), they **agree 16/16**. Of
  SemantEq's 18 disagreements with the v0.6 labels:
  - ClaimDelta reproduces the direction on 5;
  - it disagrees on 2, and in both ClaimDelta is right: `o087` is a duplicated hypothesis, and in `o141`
    the hypothesis `4 ≤ n` makes the `∨ n = 3` escape impossible;
  - it is silent on 10 (linear-only or no shared operator; by design);
  - it is inconclusive on 1.
- **No ground truth.** These cases have no ClaimDelta ground truth, so this is agreement, not accuracy.

### 4c. Not covered (by design, reported)

- **Representation changes between different operators** (`n * n` vs `n ^ 2`). No operator is shared,
  so the verdict is `NO_SHARED_SYMBOLS` and only the concrete v0.6 comparison applies.
- **Weakenings expressible in linear arithmetic alone** (`C ∨ n = 3` with `C` linear and always true).
  Here the two statements *are* the same claim in the interpreted theory, so ClaimDelta does not flag
  them; SemantEq's structural check does.
- **The mislinked `n + 0 = n` vs `n * 1 = n` case** is not detected.

## 5. Novelty screen (sources checked 2026-11-09; not exhaustive)

| Work | Method | Difference from ClaimDelta |
|---|---|---|
| SemantEq (Li et al., Oct 2026) | Restricts the *proof calculus* (allowed rewriting steps, proof-term audit) | Its non-equivalence verdicts are "Likely", with no certificate. ClaimDelta restricts the *model class*: separations come with a kernel-checked countermodel, and direction is certified. |
| BEq / BEq+ / ProofNetVerif (Poiroux et al., EMNLP 2025) | Restricted tactics (`exact?`, `simp`) in both directions | No certified non-equivalence. The authors note false positives when one side trivially proves the other. |
| Faithfulness Gap / BPF (Mohammad & Sheikh, Jun 2026) | LLM-generated probes; provability fingerprints | No symbol abstraction or countermodels; the probes are model-generated. |
| ASSESS, GTED | Operator-tree edit distance | Similarity score, not a certificate. |
| Structure-Aware Equivalence (arXiv 2610.25018, Oct 2026) | Structural role correspondence | **Could not be read in full (rate-limited).** Closest related work; must be read before any novelty claim. |

**Assessment.** We found no published method that certifies directional differences between two
*provable* statements with kernel-checked countermodels over abstracted shared operators. The ingredients
are classical: independence by countermodel, and uninterpreted functions as in SMT. The application and
the minimal-explanation structure appear to be new. **Novelty is not established**: the SAE paper and a
wider search must come first.

## 6. Limits (honest)

- **Core Lean only.** Real Mathlib statements (ℝ, sets, typeclasses) are not yet supported, and the
  witness pools cover only `Nat`, `Nat → Nat`, `Nat → Nat → Nat` and `Nat`-predicates.
- **Policy choice.** Other policies are possible, and verdicts are only meaningful *with* the policy.
- **The law list is small and fixed.** A missing law shows up as a CLAIM verdict on a harmless rewrite.
  None occurred in these tests, but that is not a guarantee.
- **No external benchmark yet.** The ProofNetVerif evaluation (V0.8 Mission E) is **PENDING**: it needs
  Mathlib support first.
- **All suites are author-written synthetic mutations.** No real paper-to-Lean error has been found.
