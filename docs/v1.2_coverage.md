Author: Caleb J. Westfall (engine and documents prepared with Claude, Anthropic).

Status: **core results are local and verified in this sandbox; every Mathlib result is PENDING** the
GitHub workflow *ProofScope v1.2 Mathlib Coverage*. The Mathlib cache is unreachable from the sandbox

## 1. The most important finding: a soundness defect in v1.1 (now fixed)

The hostile tests for this release found that frozen v1.1 gives **wrong decisive verdicts** when a
formalization *replaces* an assumption: it drops `D` and adds `A` in the same statement.

| Case | Reference | Lean | v1.1 said | Truth (v1.2) |
|---|---|---|---|---|
| z01 | `∀ n, 2 ≤ n → n + 0 = n` | `∀ n, 1 ≤ n → n + 0 = n` | ASSUMPTION_INCOMPARABLE | LEAN_STRONGER_BY_ASSUMPTION |
| z02 | `∀ n, 1 ≤ n → n ≠ 0` | `∀ n, n = 3 → n ≠ 0` | REFERENCE_NEEDS_ASSUMPTION ("reference is false") | LEAN_WEAKER_BY_ASSUMPTION (both true) |
| z03 | `∀ n, n ≤ 3 → n + 0 = n` | `∀ n, 2 ≤ n → n + 0 = n` | LEAN_WEAKER_BY_ASSUMPTION | ASSUMPTION_INCOMPARABLE |
| z06 | `∀ n, n < 0 → n + 1 = 0` | `∀ n, n < 1 → n + 1 = 0` | REFERENCE_NEEDS_ASSUMPTION | LEAN_CLAIM_FALSE |

These were run locally on frozen v1.1. Four of the seven cases in `v12_hostile` get an unsound v1.1
verdict.

**Cause.** v1.1 classified `A` and `D` separately against the shared conditions `C`:
- "restrictive" meant only that some model satisfies `C ∧ ¬A`;
- "necessary" meant some model satisfies `C ∧ ¬A ∧ ¬P`.

Neither step looks at the other changed assumption. A witness for "the reference is false" must satisfy
the reference's own assumption `D`; the z02 witness `n = 0` does not. Separate restrictiveness does not
imply incomparability either: z01 is the counterexample, proved in Lean as
`separate_restrictions_not_incomparable`.

**Fix (v1.2).** The two changes are now decided together, from six kernel-checked obligations:
- `D → A` and `A → D` under `C`;
- a model with `C ∧ A ∧ ¬D`;
- a model with `C ∧ D ∧ ¬A`;
- a model with `C ∧ D ∧ ¬P` (refutes the reference);
- a model with `C ∧ A ∧ ¬P` (refutes the Lean statement).

The new Lean theorems are `mixed_entails`, `mixed_strict`, `mixed_incomparable` and `mixed_ref_false`. A
new verdict, `BOTH_CLAIMS_FALSE`, covers the case where both claims are refuted.

**Scope of the defect.** Three existing cases (ad11, h04, h05) have mixed changes; all three still match
their labels under v1.2. h04, the only decisive one, was right in v1.1 too. **No previously reported
GitHub result is affected.** v1.1 stays frozen and unmodified; this is an erratum for v1.1, fixed in a new
version.

## 2. Design

### A. Countermodel synthesis (`proofscope/models.py`, `proofscope/adelta12.py`)

**Registry of countermodel families.** All families have decidable equality, so element-wise refutations
reduce by `decide`:

| Family | Carriers |
|---|---|
| Nonabelian groups | `DihedralGroup 3`, `Equiv.Perm (Fin 3)` |
| Abelian group | `Multiplicative (ZMod 4)` |
| Non-total partial orders | `Finset (Fin 2)`, `Bool × Bool` |
| Ring with zero divisors | `ZMod 4` |
| Field | `ZMod 3` |
| Point pools | ℝ (−2 … 2), ℤ, ℕ (plus every numeral in the statement and its successor), `Set ℕ`, `Set ℝ`, `ℕ → ℕ`, `ℝ → ℝ`, `Empty → ℕ` |

**Structure-agnostic filtering.** Instance binders are filled with `inferInstance`. A carrier without the
required class fails to elaborate inside `first`, and the next family is tried. Nothing about any case
is hard-coded: m05, m09 and m10 are not named anywhere in the engine.

**Search order (bug fix).** v1.1 concatenated the per-carrier witness lists and truncated the result at
150. Carriers late in the registry, which includes every Mathlib family, were therefore never tried for
binders with large pools. v1.2 interleaves the carriers round-robin (cap 240); a unit test covers this.
This is the most likely reason the v1.1 Mathlib run never tried a nonabelian group for m05 and m10.

**Refutations.** The universal claim is instantiated at the chosen carrier's sample elements. The goal is
then closed by `decide`, `simp`, `norm_num`, or case-splitting a disjunction. Every alternative is
wrapped `(…; done)`, there is no nested `by` inside `first`, and there is no `native_decide`.

### B. Proof search (Mathlib portfolio)

Sufficiency, redundancy and unneeded-assumption obligations try a bounded portfolio:
- decision and arithmetic tactics: `positivity`, `nlinarith` with square hints, `linarith`, `norm_num`, `simp_all`, `omega`;
- structure tactics: `fun_prop`, `continuity`, `aesop`, `group`, `ring_nf`;
- general closure lemmas: transitivity, `le_total`, `not_lt`, `pow_pos`, `Function.Injective.comp`, `Continuous.comp`, `Set.image_subset`.

Proof-search failure never produces a decisive verdict. Minimality without certified sufficiency stays
`INCLUSION_MINIMAL_IF_THEOREM_HOLDS`.

### C. Composition theorems (`lean/ProofScope/CompositionV12.lean`)

14 theorems: 12 use no axioms and 2 use only `propext` and `Quot.sound`. A fresh `leanchecker` replay
passes locally.

| Theorem | Content |
|---|---|
| `entails_transport`, `strict_transport` | entailment and strictness are invariant under an equivalence of interpretation spaces |
| `noninjective_domain_loses_strictness` | along a mere function, strictness can be lost (domain change needs care) |
| `instance_congr` | substituting a provably equal instance changes nothing |
| `assumption_and_weaker_conclusion` | adding an assumption and weakening the conclusion compose (the result is implied by the reference) |
| `assumption_vs_stronger_conclusion` | adding an assumption and strengthening the conclusion can give incomparable claims |
| `dependent_forall_mono` | entailment lifts under a dependent binder |
| `vacuous_absorbs` | under vacuous assumptions any two conclusions are interchangeable |
| `mixed_entails`, `mixed_strict`, `mixed_incomparable`, `mixed_ref_false` | the joint rule for replaced assumptions |
| `separate_restrictions_not_incomparable` | the v1.1 defect as a theorem |

## 3. Soundness argument

1. Every decisive verdict is a function of certificates accepted by the **unchanged** certify gate:
   - clean recompile;
   - standard axioms only;
   - `leanchecker` replay;
   - no `sorry`.
2. The certificates are tied to the user's statements by kernel-checked links: `R ↔ canonical` and
   `L ↔ canonical` (v1.1 linking, unchanged).
3. Each verdict is an instance of a Lean theorem:
   - single-sided changes: `restrictive_iff_strictly_weaker`, `necessary_refutes_reference` and
     `redundant_schema_equiv`;
   - replaced assumptions: `mixed_*`;
   - minimality: `inclusion_minimal` and `redundant_drop`.
4. Which carrier, instance and elements a certificate uses is read back from the kernel-checked proof
   term, never from the search heuristics.
5. Conflicting certificates produce `INCONSISTENT`, never a verdict. A conclusion change, or a dependent
   added or dropped binder, produces a non-decisive status.

**Trusted, unproved parts.**
- The extraction of the telescope (which binders and hypotheses are shared, added or dropped) is
  heuristic. It is checked only through the link certificates.
- The mapping from certificate sets to verdict names is Python code, tested by the hostile suites.

**Provenance.**
- Every case records its family, a `label_basis` (the mathematical reason for the label) and a
  `must_not_be` list (the decisive verdicts that would be wrong).
- The cases are hashed in `V12_FREEZE.txt` together with the engine files.
- They were written by the same author as the engine (Claude) without a local Mathlib. They are
  synthetic and **not independent**, and the labels are the author's mathematical judgement.

**Mix of labels.** The split includes equivalent, stronger, weaker, incomparable, both-false and minimality
cases, and cases expected to stay unresolved:
- non-distributive lattices;
- discontinuous functions;
- composite divisors outside the point pool;

The unresolved cases are deliberate: they measure coverage honestly.

## 7. Limits

- **Every Mathlib number is pending.** The eval cases were never elaborated; some may fail to elaborate.
  Those failures must be reported as such and must not be patched in place.
- **Interacting assumption and conclusion changes.** The theorems exist, but the engine still answers
  INCONCLUSIVE for these.
- **Conclusion-only changes** are routed (`CONCLUSION_ONLY_CHANGE`), not decided, by this runner. CMCD
  verdicts are schema-level, so they are deliberately not mixed into this coverage table.
- **Portfolio additions.** Some portfolio entries (transitivity, `not_lt`, `pow_pos`, a square-hint
  `nlinarith`) were added while the evaluation cases were being written by the same author. They are
  general lemmas, but the split is therefore not a blind test of the portfolio. It is a frozen,
  never-run test of the whole engine.
