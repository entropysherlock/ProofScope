## 1. The question and the answer

Can ProofScope certify what an added or dropped assumption does to a theorem's claim (hidden typeclass
assumptions, nonemptiness, decidability, a restricted domain), using the same principle as before?

**Yes, as one theorem.** Write the reference as `R = ∀ m, C m → P m` over models `m` (all binders: types,
operations, instances, points) and the formalization as `L = ∀ m, C m → A m → P m`. Then:

> **`restrictive_iff_strictly_weaker`:** `(∃ m, C m ∧ ¬ A m)` ⇔ `L` is strictly weaker than `R`, as a schema over the conclusion `P`.

So a hidden assumption is a ClaimDelta *with the conclusion as the abstracted symbol*. The certificate
is a **model**: a structure the reference covers and the formal statement excludes. This works even when
both theorems are true, where `R ↔ L` is trivially provable.

| Theorem (`lean/ProofScope/AssumptionDelta.lean`) | Content | Axioms |
|---|---|---|
| `redundant_equiv`, `redundant_schema_equiv` | `∀ m, C m → A m` ⇒ the assumption changes nothing, for every conclusion | none |
| `restrictive_iff_strictly_weaker` | the characterization above | standard (classical, for the ⇐ direction) |
| `restrictive_witness_vacuous` | at the witness model, the reference gives `P m` and the formal statement gives nothing | none |
| `necessary_refutes_reference` | a model with `C ∧ ¬A ∧ ¬P` ⇒ the reference claim is **false** without `A` | none |
| `dichotomy` | exactly one of redundant and restrictive holds | standard |
| `negative_position_strengthens` | under an implication, the comparison flips | none |
| `variance_counterexample` | an assumption added in negative position strengthens the claim (concrete instance) | none |
| `domain_restriction` | quantifying over a smaller domain `e : D → M` *is* the assumption "in the range of `e`" | none |

**Limit: dependent binders.** If the rest of the statement uses the binder (an instance used in the
conclusion), there is no well-typed statement without it, so the comparison is not defined and the
verdict is INCONCLUSIVE. Polarity is also not inferred: assumptions are compared only in the top-level
positive telescope, and anything else is INCONCLUSIVE (case `ad11`).

## 2. Engine (`AssumptionExtract.lean`, `adelta.py`)

The engine works in four steps:

1. **Align.** The elaborated binder telescopes are aligned by definitional equality. One-sided Prop
   binders (including Prop-valued typeclasses) are the assumptions; one-sided instance-implicit data
   binders become `Nonempty (Cls)`. Dependent binders are marked.
2. **Certify.** Every certificate goes through the unchanged gate: clean recompile, standard axioms,
   kernel replay. The obligations are:
   - `link_R` / `link_L`: the canonical telescopes are equivalent to the originals;
   - `redundant`, `restrictive` and `necessary`, as in §1.
3. **Search for models.** Carriers are `Bool`, `Fin 3`, `Unit`, `Empty` and `Nat`. Operation, relation
   and point pools are indexed by the carrier. Mathlib mode adds the noncommutative group
   `Equiv.Perm (Fin 3)`, ℝ points and sets of naturals.
4. **Read the witness back.** `#proofscope_witness` reads the model out of the **kernel-checked proof
   term**, so the explanation names the actual structure, e.g. `Bool` with `op a b := a`.

## 3. Boundary witness synthesis (`BoundarySynth.lean`, `cmcd_v10.py`)

**Blind-suite diagnosis (ChatGPT's 28 cases; the recorded 24/28 is kept and the labels are unchanged).**
- **`b13`, `b14` (ℤ, `a*a < a+2` vs `≤`).** Forward entailment was certified, but there was no
  separating interpretation: a fixed pool cannot contain the boundary interpretation `x a _ := a + 2`.
  *Missing principle:* separate a comparison change by interpreting the operator **on the boundary**.
  `BoundarySynth` reads every atom `x ts ⋈ e` in the elaborated chain and proposes `fun ts => e` (±1).
  The proposals only enter Lean-checked certificates.
- **`b21`, `b22` (`∃!`).** **Defect in the blind suite.** `∃!` is Mathlib notation and does not parse in
  the core Lean 4.34.1 environment the protocol specified, so the engine correctly returned INCONCLUSIVE
  ("extraction failed"). This is not an engine gap.

CMCD v1.0 wraps the frozen v0.9 engine and does not modify it.

### Soundness bug found by the adversarial suite (fixed in block 2)

**v1.0 bug.** v1.0 limited the model to the binders an assumption *mentions*. In `x01`,
`∀ α (x : α) [Nonempty α], …`, the point `x` already proves `Nonempty α`, but the engine certified the
true but irrelevant statement `∃ α, ¬ Nonempty α` and reported a restriction.
- **`ad02` (same bug, hidden).** It agreed with its label, but **the label was wrong**: the conclusion
  quantifies over `a : α`, so on empty types neither statement says anything, and the added `Nonempty α`
  is redundant.

**Block-1 summary: 2 unsound adelta verdicts.**

**Fixes.**
- v1.0.1 (prefix scope) still failed (`ad04`): a hypothesis *after* the assumption can imply it.
- **v1.0.2 uses exactly the model of the theorem: all binders and all shared hypotheses.**

## 5. Competitors

No competitor was re-run in v1.0. As published, SemantEq, ACE, BEq+ and BPF all compare whole statements
and give no certified model explaining a hidden assumption (`docs/v0.9_cmcd.md` §1). The closest
concept is ACE's role alignment, which rejects unmatched hypotheses structurally; that is a "not
equivalent" verdict, with no model and no direction. **A same-input comparison is still required** before
any superiority claim. The task definitions differ (binary vs graded), and the comparison must say so.

## 7. Candidate paper result

> **Theorem (Assumption Delta, `restrictive_iff_strictly_weaker` + `necessary_refutes_reference`).** For
> elaborated statements whose telescopes differ by a non-dependent assumption in positive position, the
> assumption changes the claim if and only if there is a model of the reference's conditions violating it.
> Such a model, read from a kernel-checked proof term, explains the change. If it also falsifies the
> conclusion, the reference itself is false without the assumption.
>
> The scope condition (the model = all binders and hypotheses) is necessary: smaller scopes give false
> certificates, as the counterexamples `x01` and `ad04` show.
